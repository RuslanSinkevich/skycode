## Что делаем (утверждено 14.10.2026)

Макет панели сверху вниз:

1. **Строка заголовка VS Code** (`view/title`): `+` (новая вкладка), MCP, аккаунт, настройки. «Часики» (`skycode.historyButtonClicked`) **убираем**, полноэкранный экран истории тоже.
2. **Полоса вкладок**:
   - слева кнопка истории (иконка боковой панели) — открывает шторку;
   - вкладки: статус-иконка + название (из первого запроса, обрезка, полное в title) + крестик (у активной всегда, у остальных при наведении);
   - `+` в конце, справа стрелка `▾ +N` — список не поместившихся вкладок.
   - Статусы: работает (спиннер), ждёт подтверждения (точка, warning), завершена (галочка), в очереди (часы), остановлена (пауза).
3. **Строки задачи (TaskHeader с названием и полосой контекста) больше нет** — лента чата сразу под вкладками.
4. **Нижняя строка**: после названия модели — маленькое кольцо заполненности контекста без цифр. Клик → всплывающее окошко над ним (без крестика, закрывается кликом мимо): «Контекст 43.5k / 128k (34%)», полоса (по возможности разбитая: история / системный промпт и правила / файлы и вывод), «N до автосжатия», кнопка «Сжать сессию».
5. **Шторка истории** — выезжает слева поверх чата (~75% ширины, фон затемняется; закрытие: клик по затемнению, кнопка, Esc): поиск, «Новый чат», группа «Открыты во вкладках» (со статусами), дальше история по датам «Сегодня / Вчера / На этой неделе / Ранее». Наведение: переименовать, удалить. Клик по открытому чату — переключает вкладку, по чату из истории — открывает в новой вкладке.

Решения:

- Модель **общая** на все вкладки.
- Режим (Акт/План/Вопрос/Дебаг/Чат) — **свой у каждой вкладки**; новая вкладка открывается в последнем выбранном.
- **Не больше 3 агентов** работают одновременно, остальные запущенные встают в очередь (статус «в очереди»). Открытых вкладок — сколько угодно.
- Открытые вкладки **восстанавливаются** после Reload Window / перезапуска — в состоянии «остановлена», продолжаются как сейчас задача из истории.
- Закрытие вкладки задачу не удаляет — она остаётся в истории.

## Риски, которые надо проверить до кода (этап 0)

Места с одним глобальным состоянием «на текущую задачу» — при нескольких параллельных агентах они начнут мешать друг другу:

- `StateManager`: `taskStateCache` + `loadTaskSettings(taskId)` — настройки задачи, кэш один.
- `mcpHub.setNotificationCallback` / `clearNotificationCallback` — один колбэк.
- `FocusChainManager`, браузерная сессия, `DiffSystem` (глобальный стор хунков — вероятно, нормально, но проверить привязку к задаче), терминал-менеджеры (создаются в `Task` — проверить общие реестры).
- `postStateToWebview` шлёт всё состояние целиком на каждое изменение — с 3 работающими агентами это 3× трафика; фоновые вкладки должны слать только статус.
- Два агента правят один файл — не блокируем, но статус «ждёт подтверждения» должен быть виден на фоновой вкладке.

Каждый этап заканчивается рабочей сборкой и отдельным коммитом (на русском). Проверка в конце каждого этапа обязательна:

```

```

Затем владелец делает Reload Window в dev host (`experiment/run-vscode.cmd`) и проверяет руками.
