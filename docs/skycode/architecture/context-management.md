# Управление контекстом

Skycode рассчитан на модели с контекстом около 100 тысяч токенов. Страница описывает, как агент экономит контекст и что происходит, когда он заполняется. Пути относительно `extensions/skycode/src/`.

## Как агент экономит контекст

| Мера | Что делает | Где |
|---|---|---|
| Диапазоны строк | `read_file` принимает `start_line` и `end_line`. Мягкий предел одного чтения: 2000 строк | `core/task/tools/handlers/readFileSlicing.ts` |
| `read_symbol` | Читает определения по имени (до 5 имён за вызов, до 400 строк на определение) с помощью tree-sitter. Комментарии и атрибуты над определением включаются | `ReadSymbolToolHandler.ts`, `readSymbolCore.ts` |
| Заглушка при повторном чтении | Если файл не менялся с прошлого чтения и прошлый результат ещё в истории, вместо текста приходит строка «File unchanged since you read it». Чтение с `start_line=1` отдаёт файл снова | `readFileSlicing.ts` |
| Правки без полного эха | Для файлов длиннее 300 строк после правки возвращаются только изменённые участки с 5 строками контекста | `core/prompts/editSnippet.ts` |
| Вывод команд | Длинный вывод сокращается до начала и конца (не больше 200 строк). Если вывод больше 1000 строк или 512 КБ, он пишется в файл, а в контекст идут первые и последние 100 строк и путь к файлу | `integrations/terminal/` |
| Служебный блок `environment_details` | Секции, которые не менялись с прошлого запроса, не отправляются повторно. Время отправляется не чаще раза в 10 минут. После обрезки истории блок отправляется целиком. Вывод терминала в блоке ограничен 40 строками и 4000 символами | `core/task/environmentDetailsDiff.ts` |
| Карта репозитория | Краткий обзор проекта в первом сообщении задачи (около 6000 символов) вместо чтения множества файлов | `services/repo-map/` |
| Дубли чтения файлов | Перед сжатием повторные чтения одного файла заменяются заглушками | `FileReadOptimizer.ts` |

## Автосжатие

Параметр `useAutoCondense` включён по умолчанию для всех моделей. Порог задаёт `autoCondenseThreshold` (доля окна, по умолчанию **0,75**). В интерфейсе этого параметра нет.

**Алгоритм:**

1. Перед каждым запросом `ContextManager.shouldCompactContextWindow()` сравнивает токены прошлого запроса с порогом.
2. Если порог превышен, сначала пробуется оптимизация чтений файлов (`FileReadOptimizer`). Если места освободилось достаточно, сжатие не запускается.
3. Иначе к сообщению пользователя добавляется промпт `summarizeTask`, и модель вызывает инструмент `summarize_task` со структурированной сводкой: задача и намерения, технические решения, изменённые файлы, нерешённое, следующий шаг и список нужных файлов (Required Files).
4. `SummarizeTaskHandler` заменяет старую историю сводкой и автоматически перечитывает до 8 файлов из списка.

**Порог в токенах** считает `getAutoCompactThresholdTokens`: это меньшее из `окно × autoCondenseThreshold` и `maxAllowedSize`. `maxAllowedSize` зависит от класса модели:

- сильные модели: окно 64k даёт 37k, 128k даёт 98k, 200k даёт 160k, для остальных окон `max(окно − 40k, окно × 0,8)`;
- средние модели: `окно × 0,7`;
- слабые модели: `окно × 0,5`.

Класс модели определяет `getModelCapabilityTier` (`src/utils/model-utils.ts`). Qwen, GLM, Hermes и Devstral в целом относятся к средним. Сильными считаются флагманы из внутреннего списка (например `qwen3-max`, `qwen3-coder-plus`, `glm-4.6`) и модели, которых нет ни в одном списке. Сильно квантованные веса (q4, gguf, awq и т. п.) на локальном или собственном шлюзе считаются слабыми. Класс можно задать вручную настройкой `sessionBudgetMode`.

## Ручное сжатие и кольцо контекста

У поля ввода стоит кольцо заполнения контекста. Клик по нему открывает окно:

- размер контекста и сколько осталось до автосжатия;
- полоса с разбивкой по категориям: системный промпт и инструменты, файлы и поиск, команды, правки, диалог, служебное, прочее;
- подсказка, если больше всего места занимает одна категория;
- кнопка **«Сжать сессию»**. Она отправляет в чат команду `/compact`. Кнопка активна, только когда агент ждёт вашего ответа (завершил задачу, задал вопрос, показал план).

Разбивку считает `core/context/context-management/contextBreakdown.ts` по сообщениям, которые реально уходят модели.

## Обрезка вместо сжатия

Если выключить `useAutoCondense`, работает прежняя обрезка. После запроса проверяется `totalTokens >= maxAllowedSize`. Сначала пробуется оптимизация чтений файлов. Если её недостаточно, из середины истории удаляется половина или четверть сообщений (первая пара user/assistant сохраняется), а в первое сообщение добавляется уведомление об удалённой истории.

## Ошибки переполнения

Если контекст всё же переполнился, `context-error-handling.ts` распознаёт ошибки провайдеров и запускает восстановление.
