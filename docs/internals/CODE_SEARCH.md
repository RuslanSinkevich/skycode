# Skycode AI — Поиск по коду (карта репозитория)

## Обзор

Основной способ, которым агент находит код. Индексация и модели эмбеддингов не нужны:

1. **Карта репозитория** — список объявлений проекта (классы, интерфейсы, методы, функции,
   свойства, процедуры/таблицы/представления SQL) с файлом и строкой. Строится tree-sitter'ом
   за секунды и обновляется по одному файлу.
2. **Текстовый поиск** — ripgrep по словам запроса; файлы ранжируются по числу разных слов
   запроса, которые в них встречаются.

Векторная индексация ([INDEXING_SYSTEM.md](INDEXING_SYSTEM.md)) — необязательное дополнение,
по умолчанию выключена.

| Проект | Файлов | Первое построение | Повторно (кэш) | Один запрос |
|--------|--------|-------------------|----------------|-------------|
| Skycode (TS) | ~980 | ~1,8 с | ~0,1 с | ~0,1 с |
| WinForms (C#) | ~210 | ~0,9 с | ~0,05 с | ~0,1 с |

## Что видит агент

- **Обзор проекта** в первом сообщении задачи (`# Repository Map` в environment details):
  самые важные файлы и их объявления, ~6000 символов. Если карта ещё строится (первый запуск
  на большом проекте), обзора в этом сообщении нет — задача не ждёт.
- **`codebase_search`** — если векторный индекс выключен или не готов, ищет по карте и тексту:

```
## Symbols matching the query (file → line: declaration)
Main/Forms/PactGraphsPayment.cs
  19: public partial class PactGraphsPayment : Form

## Text matches (files with the most query words first)
Main/Forms/PactGraphsPayment.cs (20 matches)
  338: // заполним график платежей по умолчанию
```

Промпты просят писать запрос словами-идентификаторами и предметными терминами
(«invoice payment schedule», «договор поиск»), а затем читать `read_file` только нужные строки.

## Структура файлов

```
src/services/repo-map/
  RepoMapIndex.ts        — ядро без IO: ранжирование, поиск по символам, обзор
  extractSymbols.ts      — SQL (CREATE/ALTER …) регуляркой, остальное — захваты tree-sitter
  RepoMap.ts             — IO: список файлов (rg --files), разбор, кэш на диске
  searchWithoutIndex.ts  — codebase_search без индекса: символы + ранжированный ripgrep
  __tests__/repoMap.test.ts
```

Точки подключения:
- `src/core/task/environmentDetails.ts` — обзор в первом сообщении задачи;
- `src/core/task/tools/handlers/CodebaseSearchToolHandler.ts` — поиск без индекса;
- `src/extension.ts` — прогрев карты через 5 с после запуска.

## Как устроено

**Файлы.** `rg --files` (уважает `.gitignore`) по расширениям, для которых есть tree-sitter
(`ts js py cs java go rs cpp php rb kt swift …`), плюс `sql`. Исключены `node_modules`, `bin`,
`obj`, `dist`, `build`, `out`, `packages`, `*.min.js`, `*.d.ts` и сгенерированный код
(`*.Designer.cs`, `*.g.cs`) — в WinForms-проектах дизайнеры дают в разы больше символов, чем
весь остальной код. Лимиты: 20 000 файлов, 512 КБ на файл.

**Объявления.** Запросы tree-sitter из `services/tree-sitter`; для C# дополнительно struct /
enum / record / конструкторы / свойства (каждый шаблон проверяется на совместимость с
грамматикой). SQL-объекты — регулярным выражением по `CREATE [OR ALTER|OR REPLACE]` и `ALTER`.

**Важность файла** (как repo map в Aider). Для каждого имени считается, в скольких других
файлах оно встречается, и делится на число файлов, где оно объявлено, — поэтому `get`,
`update`, `namespace App` не забивают обзор. Методы и свойства весят вчетверо меньше типов и
функций. В обзоре не показываются имена, объявленные более чем в трёх файлах, и повторы
перегрузок.

**Поиск по символам.** Совпадение со словом запроса: имя целиком > часть имени
(`getUserById` → get/user/by/id) > подстрока > сигнатура; путь файла — бонус. Каждое слово
взвешивается по редкости среди имён (IDF): «sqlite» важнее «update». Метод, совпавший только
путём файла, не показывается.

**Текстовый поиск.** Слова запроса длиной от 4 символов; у русских слов длиннее 5 символов
отрезается окончание («договора» → «догово»). Если в запросе есть кириллица, ripgrep
запускается второй раз в кодировке windows-1251 — старые проекты часто хранят исходники в ней.
Ищется в коде и в разметке/конфигах/документации (`cshtml razor xaml html vue md json xml
config yaml`), до 20 совпадений на файл, вывод — 8 файлов по 3 строки.

**Кэш.** `~/.skycode/repo-map/<hash пути>.json`. При обновлении сравниваются mtime и размер
файлов: перечитываются только изменённые. Проверка на диске — не чаще раза в 10 секунд.
При изменении формата кэша поднимается `CACHE_VERSION` в `RepoMap.ts`.
